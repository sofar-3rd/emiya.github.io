## 记忆层级

> life can only be understood ***backward***, but it must be lived ***forward***.  --Søren Kierkegaard

人类在日常生活中不断地对记忆进行编码。 通过海马体捕捉当下的体验，使记忆迅速形成并即时可用。但只有部分体验会被巩固为长期记忆。

**大部分的记忆巩固似乎发生在我们的大脑处于离线状态时**。当我们睡觉或休息时，海马体会重现并提炼最近的经历，并将它们整合到新皮层——我们大脑中储存大部分我们称之为知识的部分。

智能体记忆也可以采用类似的分工方式。智能体将大部分工作记录在日志或转录文本（transcripts）中，通过交互之间的空闲时间来重组其现有上下文，通过反思日志来组织记忆，从而修正错误或生成新的笔记和表征。这个过程被称为“**梦境**” 。

## Memory notes

智能体从**用户互动**及**任务执行**过程中保留的记忆，以上下文的形式保存下来，用于后续读取。

不包括：更改权重（修改训练中的内部参数）、上下文学习（单个会话中获取的知识）、上下文压缩（智能体对上下文的摘要）

**在人脑中，经历之前、之中或之后释放的化学信号可以将记忆标记为重要**。在离线期间，被标记的记忆比未被标记的记忆更容易被重现。这个过程被称为重现 ，它有助于稳定记忆并将其整合到长期记忆中。

类比到智能体，它们同样可以会话日志中标记重要事件，以便日后更容易找到它们，或者可以将它们写入记忆存储（db、file），**问题是如何判断哪些事件是重要的？**

![](memory-notes.png)

> Memory can be a prediction about ***what the future will need***

记忆是对未来需求的预测。通过记录规则，智能体预测它所描述的模式将来还会再次适用。例如，**记录一个已验证的事实，就相当于预测智能体在未来的会话中会想要依赖这个事实**，而无需再次核实。

## CL-Bench

持续学习基准测试[(CL-Bench)](https://continual-learning-bench.com/news/cl-bench-1-0/) 有一个特定任务，要求智能体通过在数据库中查找信息来回答一系列问题。智能体给出答案后，系统会告知它正确答案，并允许它写入记忆以帮助回答后续问题。

记忆在这里可以支持一个学习循环。**如果智能体答错了题，它可以记录下这次失败，提出关于出错原因的理论，验证这些理论，并将发现的结果转化为未来如何作答的规则**。

Anthropic 使用一个会话处理一个问题，并使用文件作为长期记忆在会话间传递信息。不同的模型在创建各自的学习循环方面取得了不同程度的成功。**模型利用记忆来捕获已验证的规则，从而更好地回答未来的问题**。

## Pokémon

在另外一项测试中，Anthropic 使用 claude 搭配不同的模型来玩 《宝可梦: 红宝石》，并给这些智能体都配置了文件来储存长期记忆。**这次评估发现更强的模型能够更有效判断信息的重要性，并能够有效组织长期记忆组织结果**。

较弱的模型 Sonnet 3.7 认为所有信息都很重要，将游戏中所有信息都写入记忆。Sonnet 3.7 在 225 个文件夹中写入了 413 个内存文件，并只获得了一个道馆勋章。而 Fable 5 在两个文件夹中编写了九个文件，外加一个名为 global.md 的顶级文件，并获得了四个徽章。

Sonnet 3.7 将一些持续变化的信息例如金钱、位置信息都记录进记忆中，**这些信息会持续变化并导致记忆信息过时**，随着游戏推进，智能体不得不花费更多的时间和资源来梳理记忆，而非进行游戏。

Fable 5 有效地组织了记忆结构，使用 global.md 文件充当了控制面板，其中包含当前目标、预先编写的道馆挑战计划（挑战可以获得徽章），以及模型自身使用内存的规则。locations 文件夹存放着特定路线的导航计划，而一个 gameplay 文件夹则存放着基于对游戏机制的理解而制定的策略。

## 引导模型

Anthropic 发现，**告诉 Claude 内存的用途很有帮助，但无需告诉它如何使用**。在 CL-Bench 测试中，我们只是告诉 Claude 有一个内存文件夹可用。这种通用指导足以让 Opus 4.7 和 Opus 5 有效地使用内存，并且都显著提升了性能

当 Anthropic 主动限制模型记忆的规则时，模型在任务的表现反而下降了，对于 **CL-Bench**，当显式设置一条“**仅记录失败**”的规则时，Opus 5 和 Opus 4.7 的性能提升都大幅下降。

## “梦境”构建新的记忆表征

通过“梦境”，智能体可以在离线状态下对 Memory Notes 构建新的记忆表征，使用的一种记忆表征被称为 [_“维基”_](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) ，它是由克劳德编写和维护的一系列页面，**收集了克劳德对某个主题的了解，并将其与其他笔记链接起来**。这些链接实际上为克劳德提供了一张地图，他可以利用这张地图筛选记忆，并在需要时高效地找到相关记忆

![](memory-representation.png)

Anthropic 使用 Stainless 公司内部文档语料库来探索维基作为记忆表示的优势。在创建初始维基后，claude 通过后续的梦境轮次来添加、编辑或精简内容。在梦境的早期阶段，Claude 的知识水平如同新员工，仅凭维基回答问题的能力有限。随着梦境的增多，其知识图谱也日渐丰富，如同经验丰富的员工。

 Claude 同时使用搜索和维基时，随着维基的不断完善，其综合得分从 54% 提升至 61%，而仅使用搜索工具时，得分仅为 53%。Claude 仅使用维基回答问题时，最高得分为 48%。此外，同时使用搜索和维基还能为每个问题节省约 20,000 个词元。

![](wiki-test-1.png)

Anthropic 同样探索了什么场景下，使用维基能够使得智能体有效地完成任务，他们使用 [Harvey LAB](https://github.com/harveyai/harvey-labs)（一个法律评测集），包含一系列问题需要智能体从资料中查找信息并生成法律摘要或给出判断。

当面对需要结合多个文档查找信息并进行判断分析的问题时（图左），Claude 在查阅维基页面时得分为 87%，而仅使用搜索功能时得分为 73%。在其他情况下，维基的作用就不那么大了。在一项实验室任务中（图右），通常只需从单个文档中进行文本搜索即可检索到简要的判断标准，维基在性能上并没有比搜索有明显的优势。

## “梦境”促进记忆点上升

梦境还可以将笔记置顶到记忆层级的顶端，代理程序可以在每次会话开始时预先将它们加载到克劳德的上下文中。

将记忆提升到新的会话中必须谨慎操作。注入的记忆会消耗宝贵的令牌，而且错误的笔记可能会被带入到每个会话中。**记忆层次结构的顶层必须保持相对较小**，而梦境的大部分工作就是维持这种状态——**通过将一些细节向下移动到层次结构中，并留下一些链接**。

[Claude Code 的自动内存管理机制](https://code.claude.com/docs/en/memory)也以同样的方式保持其注入层的大小，Claude 会在会话期间维护它。Claude 不会将所有自动内存加载到每个会话的上下文窗口中，而只会加载 `MEMORY.md` 文件的前 200 行或 25 KB。这个文件头充当索引，向 Claude 指示它知道哪些信息以及在哪里可以找到这些信息。

通过在“梦境”过程中构建特定的提示词，让智能体在构筑上层信息时，能更多关注特定目标。


## 回顾过去，展望未来

关于如何为智能体设计记忆系统，仍有许多悬而未决的问题。

**智能体何时应该创建记忆**。当智能体执行任务时，它可以将信息写入记忆存储（例如文件夹、文件或数据库），从而在源头捕捉重要信息，并使重要细节能够立即用于后续回合或会话。**即时记录笔记不可避免地会分散克劳德对主要任务的注意力**

**如何确保记忆始终保持最新**。克劳德可能会做出错误的预测，或者一开始就将错误的规则写入记忆。随着环境的变化，记忆也会发生漂移，变得无关紧要。**梦境是修正这些错误的一种方法，但这需要额外的计算**。持续检查所有记忆可能并不实际。因此，或许应该将“梦境”的重点放在可能发生变化的信息上，或者仔细调整做梦的频率（例如，根据记忆被访问的频率）。

尽管模型的能力在不断提升，但任何模型都无法真正预知未来会发生什么。“梦境”的让模型能回顾完整的过去上下文，并利用计算能力来**整理记忆**、**纠正错误**，以及**维护便于未来会话更便捷地访问记忆的表征**。
